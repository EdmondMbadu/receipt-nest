# Email Unsubscribe Setup

ReceiptNest stores global non-essential email suppressions in the Firestore `emailSuppressions` collection. Public unsubscribe requests are accepted only through signed links generated by Cloud Functions.

## Required configuration

`APP_BASE_URL` must point to the public web application, for example `https://receipt-nest.com`.

Create a dedicated signing secret before deploying the unsubscribe functions:

```bash
firebase functions:secrets:set UNSUBSCRIBE_TOKEN_SECRET
```

Use a long random value and retain it across deployments. Rotating or deleting it invalidates links in previously delivered emails.

## Deployment

The feature changes Functions, Hosting, and Firestore rules:

```bash
firebase deploy --only functions,firestore:rules,hosting
```

Hosting routes `/api/email/unsubscribe` to the one-click POST handler and `/unsubscribe` to the public Angular page.

## Behavior

- Custom admin emails and automated spend summaries honor the suppression list.
- Custom sends can include suppressed recipients only through the explicit admin override.
- Verification, password-reset, billing, security, account-deletion, receipt-processing, and test emails are not suppressed.
- Public browser links use `/unsubscribe?token=...` and never mutate state on GET.
- Direct `/unsubscribe` visits accept an email address and send a signed confirmation link. Requests are throttled per address and per IP, and entering an email never unsubscribes it immediately.
- Email-client one-click requests use a signed POST to `/api/email/unsubscribe?token=...`.
- Admins can review and restore addresses from the custom email section of `/app/admin`.
